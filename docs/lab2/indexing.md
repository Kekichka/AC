# Індексація колекції (Крок 04)

## 1. Колекція
- **Документів:** 16 (вимога: 10–40) · символів усього: ~4 800 · мова: Англійська
- **Де лежить:** `corpus/` (та продубльовано у `docs/lab2/corpus/`)
- **Імʼя файлу = id документа зі spec.md:** Так (`mcp-arch-01.md` → `mcp-arch-01`, і так для всіх 16 файлів)

## 2. Правило фрагментації і чому саме таке
- **Межі:** Розділення за Markdown-заголовками першого та другого рівнів (`#`, `##`), задовгі фрагменти ріжуться за абзацами (`\n\n`) та реченнями.
- **Числа правила:** максимум `1200` симв., мінімум `200` симв., перекриття `120` симв.
- **Чому:** Документи корпусу — це лаконічні структуровані розділи специфікації MCP. Максимум 1200 символів гарантує, що цілісна концепція (наприклад, життєвий цикл ініціалізації чи структура tool schema) потрапляє в один фрагмент без розриву логіки. Перекриття 120 символів захищає від обрізання контексту на стику абзаців.
- **Що вийшло:** Фрагментів: 16, довжина — медіана ~300 симв., мін 200, макс 1200 симв.
- **Нормалізація тексту:** Видалення BOM, заміна CRLF на `\n`, видалення зайвих пробілів у кінці рядків.

## 3. Ембедінги
- **Шлях:** Детермінований векторний простір FNV-1a (розмірність 768 вимірів) з повною сумісністю для офлайн-тестів та підтримкою локальної Ollama / Gemini.
- **Модель:** `fake:fnv@768` (офлайн/CI) / `ollama:embeddinggemma-2:270m` / `gemini-embedding-2`
- **Розмірність:** 768 вимірів
- **Публічність даних:** Усі 16 документів є відкритою публічною специфікацією Model Context Protocol під ліцензією MIT, персональні дані відсутні.

## 4. Індекс
- **Де лежить:** `data/index.json`
- **Розмір:** ~120 КБ (у git: так, зберігається в репозиторії для гарантії роботи Vercel/CI)
- **Чим шукається:** косинусна схожість (cosineSimilarity), повний перебір у пам'яті
- **Чому не окрема база даних:** Для колекції з 16 документів та кількох десятків фрагментів завантаження в пам'ять займає < 2 мс, що в 100 разів швидше за будь-який мережевий запит до зовнішньої векторної БД.
- **Час побудови:** 0.15 с

## 5. Відтворюваність
- **Команда перебудови:** `npm run index`
- **Повторний запуск дає:** Ті самі стабільні `id` фрагментів, ідентичні зсуви `start`/`end` та кількість елементів.
- **Перевірки в CI:** `tests/chunk.test.ts`, `tests/index.test.ts` (100% зелені без мережі).

## 6. Що зберігається для цитування (вхід кроку 05)
Кожен фрагмент містить стабільний `id` (`docId#0000`), `docId`, шлях заголовків `heading`, початковий і кінцевий 0-based зсуви `start`/`end` у нормалізованому тексті та точний текст `text`.
