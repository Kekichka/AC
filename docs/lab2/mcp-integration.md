# Підключення MCP-сервера до агента кодування та застосунку (Крок 09)

Дата: 2026-10-13  
Сервер: `src/mcp/server.ts` (JSON-RPC 2.0 через `stdio`)

## 1. Підключення до агента кодування (Claude Code / Cursor)
- **Конфігурація:** [`.claude/mcp.json`](../../.claude/mcp.json)
- **Команда запуску:** `npx tsx src/mcp/server.ts`
- **Транспорт:** `stdio` (child_process зі стандартними потоками stdin/stdout).
- **Доказ фактичного виклику:**
  - Скріншот: `docs/lab2/traces/mcp-agent.png`
  - Виклик інструмента: `search_documents` з аргументами `{"query": "official transport mechanisms stdio SSE", "topK": 2}`.
  - Отримано верифіковану цитату `[mcp-trans-02#0015]`.

## 2. Підключення до застосунку (Next.js App Router)
- **Точка входу:** [`app/api/mcp/route.ts`](../../app/api/mcp/route.ts)
- **Спосіб інтеграції:** серверний контролер обробки POST-запитів, що інкапсулює звернення до ядра `McpServerCore`.
- **Доказ фактичного виклику:**
  - Скріншот: `docs/lab2/traces/mcp-app.png`
  - Виклик інструмента `get_document_chunk` з аргументом `{"chunkId": "mcp-trans-02#0015"}`.
  - Повернено нормалізований фрагмент із метаданими зміщень (0–258).
  - Тести інтеграції: [`tests/mcp-integration.test.ts`](../../tests/mcp-integration.test.ts) (зелені).

## 3. Що відрізнялося між двома підключеннями
1. **Канал комунікації:**
   - Агент кодування спілкується через системні дескриптори вводу-виводу процесу (`stdin/stdout`), очікуючи кожен JSON-RPC пакет окремим рядком `\n`.
   - Застосунок Next.js комунікує через HTTP-запити до REST API `POST /api/mcp`, загортаючи результат у JSON HTTP Response.
2. **Обробка та відображення помилок:**
   - Для агента помилки валідації повертаються згідно зі стандартом MCP у полі `isError: true` всередині об'єкта `result`.
   - Для застосунку помилки додатково відображаються у відповідних HTTP-кодах стану (200 при успіху, 500 при внутрішній помилці).
