# Гібридний пошук і цитування (Крок 05)

## 1. З чого складається
- **Індекс:** `data/index.json`, ембедер `fake:fnv@768`, 16 фрагментів
- **Гілка змісту:** косинусна схожість (cosineSimilarity), топ-20
- **Гілка слів:** власна реалізація BM25 ($k_1=1.2, b=0.75$), топ-20; токенізація: `[\p{L}\p{N}]+`, стемінгу немає
- **Злиття:** Reciprocal Rank Fusion (RRF, $k=60$), бал = $\sum \frac{1}{60 + \text{rank}}$, ранги з 1
- **На вихід:** топ-5 фрагментів із цитатами
- **Вектор запиту:** детермінований FNV 768 вимірів

## 2. Формат цитати
`[docId#0000] docId › Heading · chars start–end`
- Приклад: `[mcp-trans-02#0000] mcp-trans-02 › MCP Transports · chars 0–258`
- Зсуви: 0-based у нормалізованому тексті документа
- Як читач знаходить місце: відкриває файл `corpus/mcp-trans-02.md`, знаходить вказані зміщення або заголовок
- Перевірка: функція `validateAnswer()` перевіряє, що кожен згаданий `[id]` обов'язково входив до виданих моделі фрагментів

## 4. Правило відмови (теги unanswerable)
- Порогом НЕ є бал RRF (він залежить виключно від рангів).
- **Критерій відмови:** якщо гілка слів BM25 повертає 0 результатів І векторна схожість найкращого фрагмента < 0.15 — запит позначається як `isRefusal: true`.
- Відкалібровано на запитах `q-16` (GraphQL), `q-17` (квантова криптографія), `q-18` (Redis failover) — усі три отримують відмову.
