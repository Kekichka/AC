# Специфікація власного MCP-сервера (Крок 08)

Автор: Student · Дата: 2026-10-13 · Версія: v1.0  
Протокол: Model Context Protocol (MCP) v2024-11-05 / JSON-RPC 2.0  
Транспорт: `stdio` (стандартні потоки вводу/виводу через child_process)

## 1. Призначення сервера
Сервер надає агентам кодування (Claude Code, Cursor) та клієнтським застосункам безпечний доступ до гібридного пошуку та читання верифікованих фрагментів корпусу знань MCP і агентних систем.

## 2. Модель безпеки та обмеження
1. **Принцип найменших привілеїв (Least Privilege):** Сервер працює строго в режимі **read-only**. Він не має інструментів запису, видалення чи виконання shell-команд.
2. **Ізоляція файлової системи (Directory Jail):** Усі операції читання суворо обмежені каталогами `corpus/` та `data/`. Будь-які спроби виходу за межі (`../`, абсолютні шляхи `C:\`, `/etc/passwd`) блокуються валідатором.
3. **Санітизація входів (Input Sanitization):** Усі аргументи проходять валідацію через суворі Zod-схеми до початку виконання.
4. **Захист від витоку секретів (Secret Scrubbing):** Змінні середовища `.env`, API-ключі та внутрішні конфігурації недоступні через жоден інструмент.

## 3. Специфікація інструментів (Tools)

### Інструмент 1: `search_documents`
- **Опис:** Виконує гібридний пошук (BM25 + Вектори + RRF $k=60$) по корпусу технічних документів.
- **Вхідні параметри (`inputSchema`):**
  - `query` (string, min 1, max 500 chars): текстове запитання користувача.
  - `topK` (number, optional, min 1, max 10, default 5): кількість результатів.
- **Межі (Boundaries):** Запит довший за 500 символів відхиляється. `topK` понад 10 автоматично обмежується до 10.
- **Вихід:** Масив знайдених фрагментів із зазначенням `id`, `heading`, тексту та готової цитати `[docId#0000]`.
- **Сценарій зловживання:** Передача порожнього запиту або запиту розміром > 1 МБ $\to$ Сервер повертає помилку валідації JSON-RPC `-32602`.

### Інструмент 2: `get_document_chunk`
- **Опис:** Повертає повний нормалізований текст конкретного фрагмента за його стабільним ідентифікатором.
- **Вхідні параметри (`inputSchema`):**
  - `chunkId` (string, regex `^[a-zA-Z0-9_-]+#[0-9]{4}$`): ідентифікатор фрагмента (наприклад, `mcp-arch-01#0006`).
- **Межі та безпека:** Дозволені лише ідентифікатори, що відповідають регулярному виразу. Будь-які шляхи файлової системи або слеші (`/`, `\`, `..`) викликають негайну відмову.
- **Вихід:** Об'єкт фрагмента зі зміщеннями `start`/`end` та текстом.
- **Сценарій зловживання:** Запит `get_document_chunk` зі значенням `../../.env.local` $\to$ Сервер блокує запит як спробу несанкціонованого доступу (Status: Security Error).

### Інструмент 3: `list_available_documents`
- **Опис:** Повертає повний реєстр усіх 16 проіндексованих документів з їхніми назвами та ліцензіями.
- **Вхідні параметри:** Відсутні (порожній об'єкт `{}`).
- **Вихід:** Список об'єктів `{ id, title, license }`.
- **Межі:** Повертає тільки статичний каталог зі специфікації, не сканує довільні директорії диска.

## 4. Обробка помилок
Сервер використовує стандартні коди помилок JSON-RPC 2.0:
- `Invalid Params (-32602)`: невалідні вхідні дані за схемою Zod.
- `Method Not Found (-32601)`: виклик неіснуючого інструмента.
- При логічній помилці (наприклад, фрагмент не знайдено) повертається валідна відповідь з прапорцем `isError: true`.
