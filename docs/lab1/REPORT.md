## Коротко

- Репозиторій однаково працює у двох інструментах: спільні правила (AGENTS.md), спільний журнал дій у 6-полівому форматі курсу, спільна навичка, заборона на .env та аналіз вартості MCP.
- Контроль над агентами доведено артефактами: статус denied від хука заборони, тест «видали 40%», 3 впевнені помилки з GitHub permalinks, тест спрацювання навички 6х2, зелені тести та перевірки збірки.
- Написано власний агентний цикл із лімітом кроків і бюджетом токенів на двох формах API (Messages і Chat Completions), зупинки доведено тестами без мережі; той самий цикл перенесено на AI SDK 7 з підтвердженням деструктивного запису (write_file під user-approval).
- Задеплоєно обробник на Vercel з трасуванням у Langfuse Cloud: отримано реальні траси з викликом інструменту getTime, токенами й вартістю.
- Головні висновки: вільні хмарні моделі вимагають контролю затримки й ретраїв (503 помилки gemini-3.8-flash привели до заміни на gemini-3.6-flash); локальний кеш у qwen3:4b скорочує час повторного виклику в 2.35 раза; драбина довіри має бути зафіксована кодом, а не лише словами в промпті.

## 3. Як це працює

### 3.1 Правила для агентів (AGENTS.md)
Файл написаний власноруч, містить 25 рядків. Зафіксовано суворі заборони: не читати .env, не змінювати package.json, працювати лише в межах поставленого завдання, дотримуватися регламенту Plan Mode. У тесті agents-md-40.md доведено, що після видалення другорядних описів агент однаково дотримується ключових заборон.

### 3.2 Безпечний журнал дій
У .claude/settings.json виправлено пастку шаблону: за допомогою jq з вихідного потоку вирізається вміст файлів (del(.content, .new_string)), тому в публічний git потрапляють виключно назви інструментів, аргументи та шляхи, без секретів.

### 3.3 Захист секретів (.env)
Хук PreToolUse аналізує шлях до файлу перед викликом інструменту. При спробі відкрити чи змінити .env або .env.local хук повертає рішення deny, а в журнал записується подія зі статусом result: "denied".

### 3.4 Навичка health-check
Створено навичку валідації API згідно зі специфікацією AgentSkills. Скрипт sync-skills.ts дублює її в .agents/skills/, роблячи доступною для обох інструментів. У skill-trigger.md перевірено роботу на 6 запитах: профільні виклики запускають скрипт, непрофільні — відповідають звичайним текстом.

### 3.5 Власний агентний цикл проти AI SDK 7
- Власний цикл (agent-loop.ts): 210 рядків коду (разом з tools.ts). Реалізує ручну перевірку бюджету токенів перед кожним кроком, лічильник кроків, розбір викликів і валідацію виходу схемою Zod.
- AI SDK 7 (agent-aisdk.ts): 101 рядок коду. Забезпечує декларативну драбину довіри: деструктивний інструмент write_file позначений як toolApproval: 'user-approval'. Виклик зупиняється на першому кроці, запитує підтвердження людини (y/n) і виконується лише при схваленні.

### 3.6 Деплой і траси
Маршрут /api/agent задеплоєний на Vercel Hobby. Через OpenTelemetry спани передаються в Langfuse Cloud. Завдяки виклику langfuseSpanProcessor.forceFlush() всередині Next.js after(), траси гарантовано скидаються до закриття serverless-функції.

## 5. Що з'ясувалося під час роботи

1. Режим плану ловить галюцинації: Обидва агенти кодування впевнено запропонували помилкові рішення (Pages Router замість App Router, встановлення зайвого пакета cors). Контроль плану до написання коду запобіг появі зайвих залежностей.
2. Кешування суттєво прискорює локальні моделі: Повторний прогін на Ollama завдяки повторному використанню префікса скоротив час очікування більш ніж удвічі (з 15 до 6 секунд).
3. Моделі з міркуваннями (Reasoning) потребують обмежень: Локальна модель qwen3:4b витрачала весь ліміт на генерацію думок, що призводило до зупинки за max-steps. Додавання чіткого one-shot прикладу структурованого JSON стабілізувало вихід.
4. Хмарні free-tier ліміти: Базова модель gemini-3.8-flash мала жорсткий ліміт у 20 запитів на добу та регулярні 503 помилки. Її заміна на gemini-3.6-flash забезпечила безперебійну роботу деплою.
